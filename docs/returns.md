# Возвраты по документу-основанию

Возврат покупателя ссылается на отгрузку, возврат поставщику — на приёмку.
Проверки выполняются на сервере при проведении, отмене и удалении документа
(`apps/inventory/return_limits.py`, вызывается из общего механизма проведения),
поэтому форма, кнопки, массовые действия и прямой вызов модели их не обходят.
В административной панели проведённые документы не редактируются.

## Правила

1. **Количество.** По каждому товару сумма проведённых возвратов не больше
   количества этого товара в проведённом основании. Строки одного товара
   складываются, дробные количества считаются точно. Черновики возвратов
   доступное количество не занимают.
2. **Перепроведение.** Прежнее количество самого возврата в расчёт не входит;
   повторное проведение без изменений не отклоняется.
3. **Изменение проведённого возврата** проверяется целиком в одной транзакции.
   При превышении откатываются строки, движения, остатки и стоимость. В
   сообщении — товар, количество в основании, уже возвращено другими
   документами, доступно к возврату и количество в этом возврате.
4. **Отмена и удаление возврата** освобождают количество.
5. **Основание** нельзя отменить, удалить или изменить так, чтобы товара в нём
   стало меньше уже возвращённого (в том числе убрать строку товара).
6. **Стороны.** Организация и контрагент возврата совпадают с основанием.
   Склад может отличаться: возврат покупателя на другой склад разрешён.
7. **Серийные номера.** Вернуть можно только номера из основания, которые ещё
   не возвращены другим проведённым возвратом по нему. Проверка количества
   её не заменяет.
8. **Хронология.** Возврат стоит после своего основания в общем порядке
   документов: дата, время, при совпадении — момент создания документа.
   Возврат поставщику, датированный раньше своей приёмки, отклоняется, даже
   если на складе хватает товара из другой приёмки. Приёмку (и отгрузку)
   нельзя перенести позже уже проведённого возврата по ней.
9. **Возврат без основания** не проверяется и ни к чему не привязывается.
10. **Строка отгрузки.** Строка возврата покупателя может указывать строку
    отгрузки-основания, из которой возвращается товар
    (`CustomerReturnLine.shipment_line`). По ней возврат гасит непокрытые
    единицы и восстанавливает себестоимость (`docs/cost-recalculation.md`).
    - Строка — из этого основания и с тем же товаром; по строке нельзя
      вернуть больше, чем в ней было; строку отгрузки нельзя уменьшить ниже
      возвращённого по ней (правило «не хуже» для старых превышений то же).
    - Не выбрана, но однозначна — запоминается при проведении: строка
      товара в основании одна; серийный товар — номера есть только в одной
      строке; или это единственная строка, по которой ещё не всё
      возвращено (и количества в ней хватает). Серийный товар с номерами из
      нескольких строк распределяется по номерам — каждый номер в свою
      строку; номера в выбранной строке должны быть из неё.
    - Не выбрана и неоднозначна — возврат «по отгрузке в целом»: стоимость
      восстанавливается по всем строкам товара сразу. Если у какой-то из
      строк есть непокрытые единицы, такой возврат отклоняется — строку
      нужно выбрать в форме («Строка отгрузки»).
    - **Один способ на группу.** По одной отгрузке и товару все проведённые
      возвраты считаются либо по строкам, либо «по отгрузке в целом».
      Смешение отклоняется: иначе одни и те же единицы восстанавливали бы
      стоимость дважды (было: строки 100 и 300, возврат без строки
      восстанавливал 200, затем возврат второй строки — ещё 300; на складе
      2 шт. на 500 при закупке на 400). В сообщении назван возврат без
      строки, в котором её нужно указать. Если таких возвратов несколько и
      по одному уточнить нельзя — `fix_stock_history --link` (строки
      указывает человек; см. `docs/cost-recalculation.md`).
    - Сменили основание или товар строки — ссылка сбрасывается. Удаление
      строки отгрузки, после которого её возвраты стали бы возвратами без
      строки рядом с возвратами по строкам, отклоняется.
11. **Возврат на другой склад** нельзя, пока под возвращаемые единицы товар на
    склад отгрузки не поступал (непокрытый дефицит строки). Поступившее —
    можно. Нельзя и потом отменить, удалить, уменьшить или перенести
    поступление так, чтобы такой возврат оказался непокрытым.
12. **Создание «на основании».** Черновик заполняется тем, что ещё не возвращено
    проведёнными возвратами; цены, скидки и НДС берутся из той же строки
    основания.
    - Серийный товар — по конкретным номерам: в каждой строке остаются её
      невозвращённые номера, количество — по их числу. Общий счётчик
      количества к таким строкам не применяется.
    - Остальные товары — по количеству: возвращённое с указанием строки
      списывается с этой строки, остальное возвращённое — со строк основания
      по порядку. Каждая строка черновика указывает свою строку отгрузки —
      кроме группы «по отгрузке в целом» (по ней уже есть возврат без
      строки): там строки не указываются, чтобы не смешать способы.
    - Если возвращено всё, документ не создаётся — показывается сообщение.
    Это только заполнение: окончательная проверка — при проведении, потому
    что черновиков может быть несколько.

Стоимость возврата считается как раньше (`docs/cost-recalculation.md`): полный
возврат в несколько документов восстанавливает ровно стоимость исходной
отгрузки, отклонённый возврат ничего не меняет.

## Смена основания проведённого возврата (21.10.2026)

**Закрытый дефект.** Воспроизведено независимо. Приёмка А — 2 шт., приёмка
Б — 1 шт.; по А проведён возврат поставщику на 2 шт. Тогда
`return.receipt = Б; return.save(update_fields=["receipt"])` проходило:
документ оставался проведённым, а по Б оказывалось возвращено 2 при
принятом 1. `check_returns` превышение показывал, но сохранение его не
предотвращало. Регрессионный тест — `apps/inventory/tests_return_basis.py`.

**Правило** — одно для возвратов покупателей и поставщикам
(`apps/inventory/posting.py`, правило 12).

- Основание — учётный реквизит возврата. У проведённого возврата и у
  возврата с оставшимися движениями основание меняют, ставят и снимают
  только в `editing()`. Это одна транзакция с проверкой нового основания и
  перепроведением.
  - **Проверяется:** количество, организация, контрагент, хронология, товар,
    серийные номера, строки отгрузки и действующие правила себестоимости.
  - **Прежнее основание** освобождает возвращённое.
  - **Послабление «не больше прежнего количества»** действует только для
    основания, с которым возврат проведён сейчас (по базе на входе в
    `editing()`), а не с которым объект когда-то загружен.
- **Отклоняются до записи:**
  - `save()` и `update_fields` (`receipt` / `receipt_id`, `shipment` /
    `shipment_id`);
  - устаревший объект;
  - проведение объекта с несохранённым основанием.
- **Массовая смена основания** — `QuerySet.update()`, в том числе через
  связанный менеджер основания (`receipt.returns.update(...)`),
  `bulk_update()` и `bulk_create(update_conflicts)` — не поддерживается ни у
  каких возвратов. Причина: связи строк с прежней отгрузкой снимает только
  `save()` по одному.
- **Связи строк возврата покупателя** со строками отгрузки следуют за
  основанием:
  - при смене или снятии основания связи с прежней отгрузкой снимаются;
  - при проведении строка нового основания назначается, только если она
    однозначна;
  - если однозначной строки нет, остаётся возврат «по отгрузке в целом»;
  - если и так нельзя (у части строк дефицит), операция отклоняется:
    «Укажите в возврате, из какой строки отгрузки возвращается товар», и всё
    откатывается.
- **Возврат без основания** не может ссылаться на строку отгрузки: такое
  проведение отклоняется. Снятие основания переводит возврат на действующую
  оценку возврата без основания.
- **Форма и маршруты.** В формах обоих возвратов поля основания нет: оно
  задаётся при создании «на основании», сохранение формы его не меняет.
  Админка правит только черновики. `fix_stock_history --link` уточняет строку
  через `editing()`.

## Одновременные операции

Проверка идёт под блокировкой товаров документа — той же, что у проведения,
редактирования основания и пересчёта стоимости. Порядок один для всех:
строка своего документа, затем товары по возрастанию id. Любая операция,
меняющая количество товара в возврате или в основании, держит блокировку этого
товара, поэтому два возврата последней единицы, как и возврат против
уменьшения основания, выполняются по очереди. Основание и другие возвраты
читаются уже под блокировкой, заново из базы.

Блокировки строк есть только в PostgreSQL. Тесты —
`apps/inventory/tests_concurrency.py`, на SQLite они пропускаются.

## Старые превышения

До появления проверки можно было провести лишний возврат. Такие документы
не удаляются и не изменяются автоматически. Их показывает диагностика
(только чтение, исправляющего режима нет):

```bash
python manage.py check_returns
```

Для каждого нарушения выводятся основание, товар, количество в основании,
возвращено, превышение и связанные возвраты; отдельно — возвраты, у которых
организация или контрагент не совпадают с основанием, возвраты, стоящие
в хронологии не позже своего основания, и строки возвратов покупателей,
ссылающиеся на строку не своей отгрузки-основания (основание сменили или
сняли мимо перепроведения). Такой возврат без основания провести как есть
нельзя: уберите связь строки или укажите основание (в `editing()`).

Правило «не хуже» для документов со старым превышением:

- **Можно:** перепровести возврат без изменений или с меньшим количеством,
  отменить или удалить возврат, перепровести основание без уменьшения
  количества, увеличить количество в основании.
- **Нельзя:** увеличить возврат, провести новый возврат по этому основанию,
  уменьшить количество в основании, отменить или удалить основание.

Для старого нарушения хронологии (возврат поставщику раньше своей приёмки):
документы, которые не двигали, перепроводятся как раньше; перенести приёмку
на другое время позже возврата нельзя; перенос возврата после приёмки
нарушение снимает.

Как исправлять, решает человек: отменить лишний возврат, уменьшить его или
убрать из него основание (тогда это возврат без основания — отдельный
сценарий со своей оценкой стоимости).

## Ограничения

- «Прежнее» количество документа берётся из его складских движений. У услуг
  движений нет, поэтому для них послабление «не хуже» не действует — проверка
  всегда строгая.
- Основание возврата в форме не меняется. В коде у проведённого возврата
  его меняют только через `editing()` с перепроведением; проверка идёт по
  новому основанию без послаблений (раздел «Смена основания проведённого
  возврата»).
- Выбор строки отгрузки в форме есть только у сохранённого возврата с
  основанием; у нового черновика без основания его нет.
- «Двигали ли документ» определяется сравнением его даты и времени с датой
  и временем его складских движений.
- Серийные номера сверяются по тексту строк основания и возвратов.
- Себестоимость при продаже раньше поступления — `docs/cost-recalculation.md`
  и `docs/negative-stock-proposal.md` (первый этап; закрытия периодов нет).
