# Склад — self-hosted аналог «МойСклад»

Торгово-складской учёт: контрагенты, закупки, продажи, печатные формы (PDF), остатки, деньги.

Стек: Django 6 + PostgreSQL (локально SQLite), Bootstrap 5 + HTMX, WeasyPrint.

## Быстрый старт (разработка, Windows)

```powershell
cd sklad
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env          # при необходимости отредактировать
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo   # демо-данные: admin / admin123
.\.venv\Scripts\python.exe manage.py runserver
```

Открыть http://127.0.0.1:8000 — вход `admin` / `admin123` (сменить в бою!).

## Тесты

```powershell
.\.venv\Scripts\python.exe manage.py test
```

## «Заполнить по ИНН»

Кнопка на карточке контрагента подтягивает реквизиты ЮЛ/ИП по ИНН через сервис DaData:
1. Зарегистрируйтесь на https://dadata.ru (бесплатно, лимит 10 000 запросов/сутки)
2. Скопируйте API-ключ из профиля: https://dadata.ru/profile/#info
3. В файл `.env` добавьте строку `DADATA_API_KEY=ваш_ключ` и перезапустите сервер

## Возвраты

- **Возврат покупателя** (раздел «Продажи») — товар возвращается на склад по текущей
  средней себестоимости. Создаётся кнопкой «Возврат покупателя» из отгрузки или вручную.
- **Возврат поставщику** (раздел «Закупки») — товар списывается со склада; нельзя вернуть
  больше, чем есть в наличии. Создаётся из приёмки или вручную.

Возвраты уменьшают долги во «Взаиморасчётах» (возврат покупателю — его долг нам,
возврат поставщику — наш долг ему).

## Живой поиск в документах

Контрагенты и товары в документах выбираются поиском по мере ввода (как в «МойСклад»):

- **Контрагент** — подсказки по названию, ИНН, телефону и e-mail; список ограничен ролью
  документа (в счёте — покупатели, в приёмке — поставщики). Если контрагента нет,
  пункт «Создать контрагента: …» заводит его сразу из документа.
- **Товар** — поиск по наименованию, артикулу, коду и штрихкоду. Справа показывается
  **остаток** на складе из шапки документа (красным, если нулевой), при выборе
  подставляется цена: закупочная в приёмке, продажная в счёте и отгрузке.
  Отсутствующий товар создаётся пунктом «Создать новый товар: …» (роли: администратор,
  менеджер, кладовщик), после чего его карточку можно дозаполнить в разделе «Товары».

Дополнительно:
- **Остаток в строке** — после выбора товара под ним показывается остаток на складе документа
  (красным, если ноль); при смене склада пересчитывается.
- **Сканер штрихкодов** — отсканируйте товар в поле строки: по точному штрихкоду товар
  подставится сам, появится новая строка для следующего скана.
- **Контрагент по ИНН из документа** — введите ИНН (10/12 цифр) в поле контрагента и выберите
  «Создать по ИНН» — реквизиты подтянутся из DaData (нужен `DADATA_API_KEY`).

Эндпоинты: `/api/counterparties/search/` + `quick-create`, `/api/products/search/`,
`/api/products/stock/`, `/api/products/quick-create/`.

## Импорт из Excel

Контрагенты: поддерживается прямой экспорт из «МойСклад» (включая банковские
реквизиты) и простой шаблон. Товары: простой шаблон (см. подсказку на странице импорта).
Дубли определяются по ИНН (контрагенты) и артикулу (товары).

## Печать (PDF)

Кнопка «Печать» на карточке счёта (Счёт на оплату) и отгрузки (ТОРГ-12, Акт, УПД).
Каждая форма доступна как PDF и как HTML-предпросмотр (`?fmt=html`).

Движок PDF выбирается автоматически: **WeasyPrint** (лучшее качество, боевой Linux),
с откатом на **xhtml2pdf** (чистый Python) там, где WeasyPrint недоступен — например
на Windows без GTK. Для кириллицы xhtml2pdf использует системный Arial (Windows) или
DejaVu/Liberation (Linux); в Docker для WeasyPrint нужен пакет шрифтов (см. Модуль 7).

## Развёртывание на своём сервере (Docker)

На боевом сервере всё поднимается тремя контейнерами: **Django+Gunicorn**, **PostgreSQL**, **Nginx**.
WeasyPrint и кириллические шрифты уже включены в образ.

### 1. Подготовка сервера

Нужен VPS с Ubuntu/Debian. Установите Docker:

```bash
curl -fsSL https://get.docker.com | sh
```

### 2. Загрузка проекта и настройка

```bash
git clone <ваш-репозиторий> sklad && cd sklad     # или скопируйте папку на сервер
cp .env.production.example .env
nano .env                                          # заполните ключи и пароли
```

Обязательно задайте в `.env`: `SECRET_KEY` (сгенерируйте — команда в комментарии файла),
`ALLOWED_HOSTS` (ваш домен/IP), пароли БД (`POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`),
пароль администратора (`DJANGO_SUPERUSER_PASSWORD`).

### 3. Запуск

```bash
docker compose up -d --build
```

При первом старте контейнер сам применит миграции, соберёт статику, создаст роли и
администратора. Откройте `http://<ваш-сервер>` — вход под `DJANGO_SUPERUSER_USERNAME`.

Полезные команды:

```bash
docker compose logs -f web        # логи приложения
docker compose ps                 # статус контейнеров
docker compose down               # остановить
docker compose up -d --build      # обновить после изменений кода
docker compose exec web python manage.py seed_demo   # демо-данные (необязательно)
```

### 4. HTTPS (домен + бесплатный сертификат)

1. Направьте A-запись домена на IP сервера.
2. Проще всего поставить certbot на хост-сервер и проксировать в контейнер, либо заменить
   `docker/nginx.conf` на конфиг с портом 443 и смонтировать сертификаты Let's Encrypt в Nginx-контейнер.
3. После включения HTTPS в `.env` выставьте `SECURE_COOKIES=True`, `SECURE_SSL_REDIRECT=True`,
   при желании `SECURE_HSTS_SECONDS=31536000`, добавьте домен в `CSRF_TRUSTED_ORIGINS`,
   и перезапустите: `docker compose up -d`.

### 5. Резервные копии базы

```bash
# бэкап
docker compose exec db pg_dump -U sklad sklad > backup_$(date +%F).sql
# восстановление
cat backup.sql | docker compose exec -T db psql -U sklad sklad
```

> Windows-разработка: WeasyPrint не запускается без GTK — PDF локально генерирует
> откат на xhtml2pdf. В Docker (Linux) работает основной движок WeasyPrint.

## Роли

Роль = группа Django (создаются автоматически при `migrate`):
**Администратор** (всё + настройки), **Менеджер** (продажи, контрагенты),
**Кладовщик** (приёмки, отгрузки, остатки), **Бухгалтер** (деньги, документы, отчёты).
Назначение ролей — в админ-панели `/admin/`.
